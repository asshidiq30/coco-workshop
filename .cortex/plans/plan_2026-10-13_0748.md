## Context

We have two Bronze AP invoice tables in `COCO_WORKSHOP.SOURCE_DATA` with overlapping but differently named columns. The target schema `COCO_WORKSHOP.PIPELINE_LAB` exists and is empty. Current warehouse is `DASH_WH_SI`.

Based on our earlier column analysis and the user's decisions:
- **Status**: Keep all three values (APPROVED, PENDING, VALIDATED) as-is
- **Payment terms**: Normalize Oracle `N30`/`N60` to `NET30`/`NET60`
- **Cost center vs dept**: Merge into a single `COST_CENTER` column, preserving original values

## Implementation steps

**Step 1** — Execute a single `CREATE DYNAMIC TABLE` statement:

```sql
CREATE OR REPLACE DYNAMIC TABLE COCO_WORKSHOP.PIPELINE_LAB.SILVER_AP_INVOICES
  TARGET_LAG = '1 hour'
  WAREHOUSE = DASH_WH_SI
AS
SELECT
  -- Surrogate key (source + source PK)
  MD5(source_system || '|' || invoice_id)  AS silver_invoice_key,
  source_system,
  invoice_id,
  invoice_number,
  vendor_id,
  vendor_name,
  invoice_date,
  due_date,
  invoice_amount,
  currency_code,
  payment_terms,
  po_number,
  line_description,
  gl_account,
  cost_center,
  invoice_status,
  created_at,
  -- System-specific (NULL when not applicable)
  sap_company_code,
  sap_document_type,
  oracle_org_id,
  oracle_source
FROM (
  -- SAP source
  SELECT
    'SAP'                AS source_system,
    INVOICE_ID           AS invoice_id,
    INVOICE_NUMBER       AS invoice_number,
    VENDOR_ID            AS vendor_id,
    VENDOR_NAME          AS vendor_name,
    INVOICE_DATE         AS invoice_date,
    DUE_DATE             AS due_date,
    INVOICE_AMOUNT       AS invoice_amount,
    CURRENCY_CODE        AS currency_code,
    PAYMENT_TERMS        AS payment_terms,      -- already NET30/NET60
    PO_NUMBER            AS po_number,
    LINE_DESCRIPTION     AS line_description,
    GL_ACCOUNT           AS gl_account,
    COST_CENTER          AS cost_center,
    APPROVAL_STATUS      AS invoice_status,
    CREATED_AT           AS created_at,
    SAP_COMPANY_CODE     AS sap_company_code,
    SAP_DOCUMENT_TYPE    AS sap_document_type,
    NULL                 AS oracle_org_id,
    NULL                 AS oracle_source
  FROM COCO_WORKSHOP.SOURCE_DATA.BRONZE_SAP_AP_INVOICES

  UNION ALL

  -- Oracle source
  SELECT
    'ORACLE'             AS source_system,
    INV_ID               AS invoice_id,
    INV_NUM              AS invoice_number,
    SUPPLIER_ID          AS vendor_id,
    SUPPLIER_NAME        AS vendor_name,
    INV_DATE             AS invoice_date,
    PAYMENT_DUE_DATE     AS due_date,
    TOTAL_AMOUNT         AS invoice_amount,
    CURRENCY             AS currency_code,
    REPLACE(REPLACE(TERMS_CODE, 'N30', 'NET30'), 'N60', 'NET60')
                         AS payment_terms,
    PURCHASE_ORDER       AS po_number,
    DESCRIPTION          AS line_description,
    ACCOUNT_CODE         AS gl_account,
    DEPT_CODE            AS cost_center,
    STATUS               AS invoice_status,
    CREATION_DATE        AS created_at,
    NULL                 AS sap_company_code,
    NULL                 AS sap_document_type,
    ORACLE_ORG_ID        AS oracle_org_id,
    ORACLE_SOURCE        AS oracle_source
  FROM COCO_WORKSHOP.SOURCE_DATA.BRONZE_ORACLE_AP_INVOICES
)
```

Key design choices:
- **`SILVER_INVOICE_KEY`** — MD5 surrogate key from `source_system || '|' || invoice_id` to guarantee uniqueness across systems
- **`SOURCE_SYSTEM`** — discriminator column (`SAP` or `ORACLE`)
- **Payment terms** — `REPLACE` normalizes Oracle `N30`→`NET30`, `N60`→`NET60`
- **System-specific columns** — carried as NULLable columns rather than dropped
- **`TARGET_LAG = '1 hour'`** — reasonable default for Silver-layer refresh
